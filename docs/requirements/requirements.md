# 需求文档:通用 AI 浏览器操作助手(Browser Agent)

> 文档版本:v2.0
> 状态:实现中(2026-08-14);E1-E6 已完成(通用 DOM 工具层 / 薄 loop + provider tool use / 安全确认与过程展示 / S1 数据提取 / S2 表单 / S3+S4 发布·研究),E7 测试与文档同步进行中
> 上游决策:通用 AI 操作任意网页 DOM;4 场景做深;飞书降级为普通场景

---

## 1. 背景与目标

### 1.1 背景
M1 完成了"飞书文档 AI 助手"(读文档 → 对话 → 写回)。用户核心诉求是 **AI 能操作网页**。故从飞书专用升级为**通用浏览器智能体**:用户给目标,AI 自主规划并操作任意网页 DOM 完成目标。

### 1.2 目标
- 侧边栏对话式输入目标(AI 助手样式,保留)
- AI 通过**浏览器工具**操作当前页面:读取/点击/输入/滚动/等待/提取/导航
- AI 多步规划:观察→操作→再观察,直到完成或询问
- **安全确认**:提交/发布/支付等敏感操作前暂停征得用户确认
- 飞书不再特殊对待,其读/写能力并入通用工具

## 2. 场景(4 个,均做深)

| 编号 | 场景 | 典型任务 | 验收闭环 |
|---|---|---|---|
| S1 | **网页数据提取** | 列表页/后台表格/卡片 → CSV/Excel/JSON | 可下载导出 |
| S2 | **表单与流程自动化** | 问卷/报备/注册/审批多步填表 | 停在提交前等确认 |
| S3 | **多平台内容发布** | 一段内容 → 公众号/知乎/论坛多平台 | 每平台发布前确认 |
| S4 | **网页研究总结** | 多页资料 → 总结/对比/要点 | 输出结构化结果 |

## 3. 核心能力

### 3.1 浏览器工具集(content script 提供,经消息执行)
- `readPage`:页面可交互元素(按钮/输入/链接/表单)+ 文本摘要
- `clickElement(sel)` / `typeInto(sel, text)` / `scrollTo(sel)` / `waitFor(sel)` / `sleep(ms)`
- `extractData(sel)` → 表格/列表 → CSV / JSON
- `navigate(url)`(background)
- `getUrl` / `getTitle`
- 危险工具(`evaluate` JS)默认禁用,可配置开启

### 3.2 AI 规划(Agent Loop)
- LLM **function calling / tool use**:返回工具调用 → 执行 → 结果回填 → 继续
- 每场景独立 system 提示词(规划策略 + 工具约束)
- 循环上限、超时、可手动停止

### 3.3 对话式侧边栏(保留演进)
- 展示 AI 思考、工具调用、页面观察、结果;关键步骤确认弹层
- 会话历史(已有)

### 3.4 多 provider(保留)
- Anthropic(tool use)/ DeepSeek / OpenAI 兼容(tool calling),流式

## 4. 安全(重点)
- **敏感操作白名单**:点击"提交/发布/保存/删除/支付"等按钮前必须用户确认
- 用户可随时停止;执行记录可见
- `evaluate` 默认禁用
- 不做跨域数据回传(内容仅发送给用户所选 provider)

## 5. 非功能
- 工具执行可靠;失败回填给 AI 重试
- 新增场景 = 新增 system 提示词 + 工具组合,引擎复用
- DOM 结构变化鲁棒(语义/可访问性优先)

## 6. 里程碑(建议)
| 阶段 | 内容 |
|---|---|
| E1 引擎 | 通用 DOM 工具层 + provider tool use + Agent Loop + 安全确认 |
| E2 场景 S1 | 数据提取闭环(页面→CSV 导出) |
| E3 场景 S2 | 表单自动化(填表→停提交前确认) |
| E4 场景 S3/S4 | 多平台发布、研究总结 |
| 存量 | 飞书读/写工具并入通用工具集 |

## 7. 已确认(设计补全,2026-08-13)
- **推进顺序**:E1(通用 DOM 工具层)→ E2(provider tool use + Agent Loop)→ E3(安全确认 + 过程展示)→ E4 场景 S1 数据提取(首个做深场景,闭环清晰、最能验证引擎)→ E5 S2 → E6 S3/S4 → E7 测试与文档同步
- **数据导出形式**:**CSV 文件下载 + 复制到剪贴板都支持**(侧边栏对 extractData 结果提供两键);JSON 作为 `extractData` 的结构化返回内部载体
